# シーケンス図全体の差分同期：実装計画と進捗

## 完成条件

表示中の図で「PlantUMLを反映」を押し、ファイルを選ぶと、対応情報の作成・照合・反映・読戻しまで完了する。PlantUMLを意味上の正本とし、共通部分のIDと表示設定を保持する。曖昧な最小範囲は再作成する。レイアウトは必要な範囲だけ移動する。参照先の別図は変更しない。

対象は参加者、メッセージ、実行区間、生成・破棄、複合フラグメント、オペランド、Note、ref。refは完全名、一意な単純名の順で解決する。同名候補が複数なら選択し、見つからなければリンクなしで続行する。識別子コメントをPlantUMLに追加しない。

対応情報は補助情報とし、なくても現在図から再構築する。プロジェクトを自動保存しない。反映を一つのトランザクションに収め、失敗時は取消しと復元の読戻しを行う。要素ごとの実機検証後に通常のPlantUMLタブへ統合する。

## 実装順と次の実機ゲート

1. **現在の段階**：各種要素を含む図を出力し、無編集のPlantUMLで「図全体の差分を検証」を実行する。無変更なのに出る候補と要照合項目を確認し、読取り・正規化・出力の食い違いを修正する。
2. SDKのモデル更新アダプターを実装する。順序はメッセージ復元と実行区間、参加者、フラグメントとオペランド、Note、ref。実験では一時図を使い、取消後の除去を確認する。
3. `SyncPlan`から変更データとEditor全体を組み立てる。共通モデル・関連・図形IDと未知属性を保持し、変更部分だけを書き換える。現在の新規図生成器による全体再生成を差分更新として使わない。
4. 複数種混在・再実行・失敗注入を確認する。実機でUndo/Redo・保存・再読込・Git差分を確認する。
5. 対応情報を再構築可能なローカルキャッシュへ移し、通常タブの一回操作へ統合する。実機未確認の構造変更を通常コマンドへ公開しない。

最初のゲートに必要なのは現在図の読取り結果。全モデルの新しい診断を別操作で要求せず、このコマンドが保存するレポートを使う。

## 検査とソース構成

`SequenceImportProbe/sync/`が新しい同期処理の正本。0.12.0 から DLL 方式になり、`SequenceImportProbe.csproj` が `sync/` と `src/` と `PlantUmlTool/src/10-sequence-export.cs` を直接ビルドする（`bundle.py` と main.cs の生成区画は廃止）。テストは csproj と同じ並びのソースを読む。

```powershell
python SequenceImportProbe/tests/run_tests.py --build
```

診断レポートは実行PCの`%LOCALAPPDATA%\NextDesign.SequenceSync\reports`へ保存する。JSONには入力・現在図・対応ID・変更候補・要照合項目が含まれる。モデル名やIDを含むため、公開リポジトリへ追加しない。

ローカル検査は全種類の差分計画、同名・入れ子、移動、連続追加削除、再実行、局所配置、ref候補解決と既存回帰を対象とする。公式SDKコンパイルはAPIの利用可否を確認するもので、実機での読取り・反映・取消を実証するものではない。

## 構造更新の事前判定（0.8.20）

差分計画に対する純粋な事前判定を追加した。既存実行区間への受信接続変更と未参照区間削除を候補として抽出し、未対応操作の混在や受信区間なしを停止理由として保持する。候補ありは実モデルへの適用可否を保証しない。書込み時のモデル共有・編集可否・退避データと現状態の一致・スタイル保持の検査は引き続き必要。

現在の残作業は、受信区間なしの表現確定、既存図の退避データからの更新ペイロード構築、適用・取消後照合。事前判定は未対応差分を消さず、書込み可能な部分だけを反映する動作も行わない。

次は準備データの実機確認と、トランザクション内での適用・読戻し・取消の実装。適用時の現状態との一致確認、共有モデルの影響検査、スタイル・配置の保持検証は省略しない。受信実行区間なしの入力表現は引き続き未解決。

## 既存図での一時適用と取消（0.8.22）

UPDATE005はその場で作成した準備データだけを使って接続変更・区間削除を試し、成功・失敗にかかわらず取消を1回行う。SDKで読み戻したモデル・関連・ポート・図形・配置を、接続変更後、削除後、取消後に照合する。シリアライズされた未知属性は準備データに保持するが、変更後のスタイル読戻しは未検証。

失敗注入を含むローカルテストは合格。未使用区間削除1件の検証サンプルを追加し、既存図からの準備・一時適用・取消の実機確認を次の工程とする。通常の確定処理、保存再読込、受信区間なしの表現は未完。

## 未対応の構造差分に対する方針（0.8.30）

事前判定が受理するのは「既存実行区間への受信接続変更」と「未参照実行区間の削除」の2種類だけで、残りは停止理由に積んで全体を止める。受理範囲を広げる前に、要素ごとにID保持・参照・配置・取消の条件を先に決める。以下は決めた条件と、次に実機で確かめる最小の1操作。観測していない項目は未観測と書き、推測で埋めない。

共通の前提は3つ。未対応が1件でも混ざれば全体を停止し、対応できる部分集合だけを適用しない。要素ごとに実機1ケースが通るまで通常コマンドへ公開しない。順序番号は関連元モデルのフィールド単位で、削除するとそのフィールド内だけが詰まる（0.8.30 の診断で実機確認済み）。追加・挿入側の規則は未観測なので、要素ごとに確かめる。

### 受信実行区間のないメッセージ

- ID保持: メッセージIDは保持する。受信端をどう表すかが未定のため、それ以上は決めていない。
- 参照: ReceiveMessageのSourceはメッセージポート型で、ライフラインは型不一致で拒否される。長さ0の区間やMessageEndを補って一致させない。
- 配置: 未定。
- 取消: 未定。
- 次の最小1操作: 受信区間のないメッセージをNext Design側で作れるかを確認する。作れないなら入力側の制約として明示し、この差分は停止理由のまま残す。

### 実行区間の追加

- ID保持: 追加分は新規ID。既存要素のIDは触らない。
- 参照: 追加先ライフラインのOwnedExecutionSpecificationと、相互作用の___Interaction_ExecutionSpecificationの2本が要る。入れ子（outer）を持つ場合の関連は未観測。
- 配置: 図形を新規に作り、既存図形の座標は動かさない。横位置は生成器と同じ規則を使う。ライフライン図形の X に幅の半分を足した中心から、入れ子の深さ 1 ごとに 8px 右へずらす。縦位置は接続するメッセージから決める。既存区間の長さ変更が要るケースは別の差分として扱う。
- 取消: 同一IDでの再作成と取消復元は一時図で成功している。既存図での追加取消は未観測。
- 次の最小1操作: 同じ参加者の既存区間に別のメッセージが残る状態で、1本のメッセージの受信先を新しい入れ子区間へ移して取り消す。候補の抽出は 0.8.33 で実装済み。既存区間が他のメッセージで固定されていないと、差分計画は新しい区間を外側の追加と読むため、アンカーのある形だけを対象にする。

### 実行区間の移動（所属・入れ子の変更）

- ID保持: 既存IDを保持する。
- 参照: OwnedExecutionSpecificationのSource端を別ライフラインへ付け替える。システム定義関連へのRelateは拒否されるので、JSON取込でSourceIdを書き換える経路になる。移動元ではフィールド内が詰まり、移動先では挿入される。挿入側の規則は未観測。
- 配置: 横位置は移動先ライフラインへ追従させる。縦位置と長さは保持する。
- 取消: 未観測。
- 次の最小1操作: 実行区間1本の所属を別ライフラインへ移して取り消す。0.8.30が出す所有コレクションの順序一覧を記録する。

### 参加者の追加・削除・並び替え

- ID保持: 追加は新規ID、削除は残存参照がない場合だけ、並び替えは既存IDを保持する。
- 参照: 参加者は実行区間・メッセージ・Note・refから参照される。削除は全参照が消えた後にしか行わない。並び替えは相互作用のライフラインコレクションの順序変更で、全メッセージの横座標に効く。
- 配置: 並び替えは図全体の再配置を伴う。現在の局所配置では足りない。
- 取消: 未観測。
- 次の最小1操作: 参加者を1本追加して取り消す。並び替えは横座標の再計算方針が決まるまで停止理由のまま残す。

### フラグメント・オペランド

- ID保持: フラグメントとオペランドは別要素として扱い、オペランドだけの追加削除で既存フラグメントのIDを保持する。
- 参照: 内側の要素はオペランドに所属する。所属変更は入れ子の付け替えになる。境界をまたぐ実行区間はA09のまま未確定。
- 配置: 枠の高さは内側の要素で決まる。既存の枠座標を保ったまま内側だけ変えられるかは未観測。
- 取消: 未観測。
- 次の最小1操作: 既存フラグメントにオペランドを1つ追加して取り消す。

### Note

- ID保持: 既存IDを保持する。本文だけの変更は属性更新として扱う。
- 参照: 対象はライフライン・メッセージ・実行区間のいずれかで、自由配置Noteは対象なし。現在の入力構文との対応はA07のまま未確定。
- 配置: 自由配置Noteの座標は保持する。対象付きNoteの座標がSDK側で決まるかは未観測。
- 取消: 未観測。
- 次の最小1操作: 対象付きNoteを1つ追加して取り消す。

### ref

- ID保持: 既存IDを保持する。
- 参照: 表示枠と参照先リンクは別物で、現在は枠と本文だけ作りリンクは設定しない。リンク書込みは候補解決（完全名、一意な単純名の順）を先に確定させる。
- 配置: 枠の座標を保持する。
- 取消: 未観測。
- 次の最小1操作: 既存refの参照先を1件設定して取り消す。

### 生成・破棄

- ID保持: 生成・破棄メッセージのIDを保持する。破棄点は別要素として扱う。
- 参照: 破棄関連の方向は修正済み。生成構文の正規化はA10のまま未完。
- 配置: 破棄点はライフライン上の縦位置。生成はライフラインの開始位置を下げる。
- 取消: 未観測。
- 次の最小1操作: A10の正規化が済むまで着手しない。

### メッセージの追加・削除・移動

- ID保持: 追加は新規ID、削除と移動は既存IDを保持する。本文更新とメッセージ削除は別経路で実機確認済み。
- 参照: 送受信の実行区間と参加者への接続。順序は相互作用のメッセージコレクションで、挿入削除で後続の索引が動く。受信関連と同じ問題が出る。
- 配置: 縦位置は前後のメッセージから決める。既存メッセージを動かす範囲を限定する。
- 取消: 既存の削除経路で確認済み。差分同期のトランザクション内では未観測。
- 次の最小1操作: 既存経路を差分同期のトランザクションへ取り込み、追加1件と削除1件を同時に試行して取り消す。
