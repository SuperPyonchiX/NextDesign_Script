# AgentReview（AI レビュー）

Next Design の設計を、Claude Code または Codex のエージェントにレビューさせる拡張機能です。選んだモデルの設計情報と図をファイルに書き出し、ターミナルでエージェントを起動します。エージェントは開発工程に合った観点でレビューし、指摘と修正提案をファイルに残します。結果は VS Code で読めます。

- 対話はターミナル上の claude / codex の画面で行います。
- エージェントが Next Design のモデルを書き換えることはありません。修正提案を読んで、Next Design 上で反映するのは人です。

## 必要なもの

- Next Design V3.x
- Claude Code（`claude`）または Codex（`codex`）の CLI。PATH が通っていること。リボンの「環境診断」で確認できます。CLI をインストールした直後は Next Design を再起動してください。
- VS Code（「結果を開く」で使います。追加の拡張機能は不要です）
- 変化点レビューを使う場合は Git for Windows

## インストール

配布された `AgentReview` フォルダ一式（`AgentReview.dll`・`manifest.json`・`skills` など）を次のどちらかに置き、Next Design を再起動します。

| 置き場所 | 使える人 |
|---|---|
| `%LOCALAPPDATA%\DENSO CREATE\Next Design\extensions\AgentReview\` | 自分だけ |
| `C:\ProgramData\DENSO CREATE\Next Design\extensions\AgentReview\` | その PC の全ユーザー |

更新するときは Next Design を終了してからフォルダの中身を入れ替えます。起動中は差し替えられません。

リボンに「AI レビュー」タブが出ます。

| グループ | ボタン | 内容 |
|---|---|---|
| エージェント | レビュー開始 | 選んだモデルをレビューする |
| | ターミナル再開 | 直近のレビューの対話を続ける |
| | 変化点レビュー | Git の過去版と比べ、変わった部分をレビューする |
| 出力 | 設計情報を出力 | レビューせずに設計情報と図だけを書き出す |
| 結果 | 結果を開く | 直近のレビュー結果を VS Code で開く |
| | フォルダを開く | 直近のレビューのフォルダをエクスプローラーで開く |
| 設定 | エージェント切替 | Claude Code と Codex を切り替える |
| | スキルを開く | レビュー手順と工程別の観点表を開く |
| | 設定 | 保存先・エージェント・VS Code などを設定する |
| | 環境診断 | claude / codex CLI の有無とバージョンを表示する |
| | エクスポート診断 | 設計情報に出ない項目を調べるため、モデルの中身を書き出す |
| | 過去版出力の検証 | 過去版のプロジェクトから本文と図が出力できるかを試す |

## レビューする

1. ナビゲータでレビューしたいモデルを選び、「レビュー開始」を押します。
2. 選択画面で、対象の工程（要件分析／アーキ設計／詳細設計）を選びます。
3. 上位文書を選びます。詳細設計ならアーキ設計、アーキ設計なら要件分析書が上位にあたります。
   - モデルはツリーでチェックします。チェックしたモデルは配下も含めて渡します。モデル名やパスで検索できます。
   - Word・Excel・PDF などの資料は「資料ファイルを追加」で選びます。
   - 上位文書を使わない場合は「今回は上位文書なし」を押します。この場合、上位要求との整合は「未確認」として結果に残ります。
4. 「レビュー開始」を押します。初回だけ、レビュー結果の保存先フォルダを聞かれます。
5. ターミナルでエージェントが起動し、自動でレビューを始めます。工程はすでに伝わっているので、聞き直されることはありません。途中で質問されたらターミナルで答えてください。
6. 終わったら「結果を開く」を押します。VS Code に結果がプレビュー表示されます。

選択画面の内容はプロジェクトと工程ごとに記憶され、次回は前回の選択が入った状態で開きます。「今回は上位文書なし」を選んでも、記憶した選択は消えません。「キャンセル」では何も保存・作成されません。保存していないプロジェクトでもレビューはできますが、選択は記憶されません。

対話を途中でやめた場合は、「ターミナル再開」で続きから再開できます。エージェントが作業を終えたかどうかを拡張機能は検知しないので、結果がそろったかは「結果を開く」で確認してください。

### レビューに使われる情報

- モデルは Next Design で開いている現在の内容を使います。保存していない編集も含まれます。
- 資料ファイルはディスクに保存されている内容を使います。編集中の資料は先に保存してください。
- 資料はレビュー開始時点の内容をコピーして使います。Excel・Word・PDF がどこまで読めるかはエージェント側の環境によります。読めなかった範囲は「判断できない」として結果に残ります。
- プロジェクトファイルと同じ場所に `Attachment` フォルダがあれば、エージェントからも見えるようにします（コピーはせず、元のフォルダを参照します）。

## 結果の見方

「結果を開く」で、直近のレビューのフォルダが VS Code の新しいウィンドウで開きます。

| ファイル | 内容 |
|---|---|
| `review/review.md` | 指摘の一覧 |
| `review/coverage.md` | 上位文書の要求が設計に反映されているかの対応表 |
| `review/proposal.md` | 修正提案 |
| `review/proposed/` | 修正後の図（PlantUML） |
| `design/design.md` | レビューに渡した設計情報 |
| `design/_index.md` | 図の一覧 |
| `design/diagrams/` | 図の PlantUML（`クラス図` / `シーケンス図` / `状態遷移図` ごと） |
| `upstream/` | レビューに渡した上位文書 |
| `inputs.md` | 何を入力にしたか（対象モデル、資料、日時など） |

結果がまだないときは案内が出ます。プレビューではなく編集画面で開きたいときは、VS Code の「エディターを再度開く…」からテキストエディターを選んでください。VS Code が見つからない場合は、「設定」の「VS Code」で `Code.exe` を指定します。

レビューのフォルダを削除するときはエクスプローラーで削除してください。PowerShell 5.1 の `Remove-Item -Recurse` は、参照している元の `Attachment` の中身まで消すことがあります。

## 変化点レビュー

Git で管理しているプロジェクトで、過去のコミットと今の設計を比べ、変わった部分とその影響をレビューします。

1. Git 管理下の保存済みプロジェクトを開き、比べたい成果物のモデルを選んで「変化点レビュー」を押します。
2. 通常のレビューと同じ画面で、工程と上位文書を選びます。
3. 比較元のブランチまたはタグを選び、一覧からコミットを選びます。履歴は100件ずつ追加で表示でき、表示中の項目を検索できます。
4. 拡張機能が過去版を取り出します。過去版でプロジェクトファイルの場所が違う場合は、候補から選びます。
5. 成果物はモデル ID で対応させます。過去版に同じ ID がなければ、ツリーから選ぶか「過去版にはない新規成果物」を選びます。
6. 差分があればエージェントが起動します。差分がなければエージェントは起動せず、保存先を案内します。

知っておくこと:

- 比較するのは「今開いている内容（未保存の編集を含む）」と「選んだコミット」です。上位文書は現在版だけを使います。
- 手元にあるコミットだけを使います。fetch や checkout はしないので、作業中のファイルは変わりません。
- 過去版に LFS・サブモジュール・シンボリックリンク・Windows で扱えない名前が含まれていると止まります。プロファイルや分割モデルなど、開くのに必要なファイルは同じリポジトリに入れておいてください。
- 進捗画面からキャンセルできます。

結果は通常のレビューと同じフォルダ構成に加え、次のファイルができます。

| ファイル | 内容 |
|---|---|
| `diff/changes.md` | 機械的に取り出した変更の一覧 |
| `review/changes.md` | エージェントがまとめた変更の概要と影響範囲 |
| `baseline/` | 過去版のプロジェクトと設計情報 |

## 設計情報だけを出力する

「設計情報を出力」を押すと、レビューせずに `design.md`・`_index.md`・`diagrams/` を選んだフォルダへ書き出します。エージェントは起動しません。既にあるファイルは自動では消さないので、新しいフォルダを選ぶのが確実です。

## 図の扱い

- シーケンス図・クラス図・状態遷移図は PlantUML（`.puml`）として書き出され、`design.md` の該当箇所から参照されます。
- フォルダは、図をまとめているグループの名前から階層を作ります。通常は設定不要です。
- 内容を取り出せなかった図は、空の図とはみなさず `unverified-diagrams.md` に「未確認」として記録します。レビューは止めずに続けます。未確認の図は Next Design 上で確認してください。

## 設定

リボンの「設定」で開きます。「保存」で反映され、Next Design の再起動は不要です。

- **基本設定**: エージェント、ターミナル、レビュー結果の保存先、VS Code の場所、追加のレビュー観点
- **詳細設定**: CLI のコマンド名と追加引数、起動時に送るメッセージ、図の階層ルール。通常は変更不要です。

新規に使い始めたときのエージェントは Codex です。「エージェント切替」でも切り替えられます。

## レビュー観点を変える

レビューの進め方と工程別の観点表は、拡張機能に同梱した `skills/design-review/` にあります。「スキルを開く」で中身を確認できます。

観点はチームで共通です。変えたいときは手元で直さず、拡張機能の管理者に依頼してください。更新した拡張機能を配布し直すと、次のレビューから反映されます。

## 困ったとき

| 症状 | 対処 |
|---|---|
| エージェントが起動しない | 「環境診断」で CLI が見つかるか確認する。インストール直後なら Next Design を再起動する |
| 選択画面が開かない・エラーになる | エラー画面に出る診断ログ（`%USERPROFILE%\.nd-agent-review\diagnostics\picker-*.txt`）を管理者に送る |
| 「スクリプトの実行が無効」と出る | 古い版のメッセージです。拡張機能を最新版に入れ替えて Next Design を再起動する |
| 設計情報に出てほしい項目が出ない | 対象モデルを選んで「エクスポート診断」を実行し、出力を管理者に送る |
| 結果を開いても何も出ない | エージェントがまだ作業中の可能性がある。ターミナルを確認する |

開発・保守向けの情報（仕組み、ビルド、テスト、変更履歴）は [DEVELOPMENT.md](DEVELOPMENT.md) にあります。
