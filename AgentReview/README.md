## 0.13.1 の実装状況

「レビュー開始」で、設計自体の工程別観点と上位要求との整合をまとめて確認する。設定された上位モデル・外部資料とAttachmentを固定コピーし、要求の反映を `review/coverage.md` に記録する。上位文書が未指定なら、その整合は未確認として結果に残す。操作と実機確認は [VERIFY.md](VERIFY.md) を参照。

| 機能 | 状態 |
|---|---|
| レビュー開始 | 設計自体と上位要求との整合を一括レビュー。模擬SDKで検証済み、Next Design実機は未確認 |
| 過去版出力の検証 | フォルダとプロジェクトファイルを画面から選択。設定ファイルの編集は不要。実機での本文・図の取得は未確認 |
| Gitからの取得・変化点レビュー | 実装済み。実Git・模擬SDKで検証。Next Design実機との一連の連携は未確認 |

「変化点レビュー」は過去コミットと現在開いている工程成果物を比較する。過去版のフォルダ準備や設定ファイル編集は不要。NdMcpへの依存はない。

## 変化点レビュー

1. Git管理された保存済みプロジェクトを開き、比較する工程成果物モデルを選択して「変化点レビュー」を押す。
2. 既存画面で工程と現在版の上位文書を選ぶ。
3. 比較元のブランチ・タグ（既定候補はHEAD）を選び、日時・コミットID・メッセージの一覧からコミットを選ぶ。履歴は100件ずつ追加表示でき、検索は表示済みの項目に対して行う。
4. 拡張が現在版を固定してから、過去コミットを自動取得する。過去版でプロジェクトファイルが移動していた場合は、取得済みファイルから選ぶ。
5. 成果物はモデルIDで対応させる。過去版にIDがない場合はモデルツリーから選ぶか、「過去版にはない新規成果物」を選ぶ。
6. 差分があればエージェントを起動する。差分がなければAIを起動せず保存先を案内する。「結果を開く」でVS Codeに結果を表示する。

比較先はNext Designの未保存編集を含む固定出力。外部資料はディスク上の保存済み内容を使う。上位文書は現在版のみで、上位文書自体の版間比較はしない。プロジェクト全体ではなく選択成果物と配下を出力する。

| 保存先 | 内容 |
|---|---|
| `design/` | 現在版の本文・図・添付資料・比較索引 |
| `baseline/project/` | 確定コミットから取得した一式 |
| `baseline/design/` | 対応する過去版成果物の出力 |
| `upstream/` | 現在版の上位文書の固定コピー |
| `diff/changes.md` と前後ファイル | 機械生成の変更一覧・根拠 |
| `review/changes.md` | AIによる変更概要・影響範囲、または差分なしの報告 |
| `session.ini` / `inputs.md` | コミット、対象ID、対応方法、処理状態、入力条件 |

Git for WindowsがPATHから起動できることが必要。ローカルに存在するコミットだけを使い、fetch・checkoutは行わない。過去版はGitオブジェクトの内容を取得し、作業ツリーの変更や `.gitattributes` の `export-ignore` に影響されない。

初版では、展開対象にLFSポインタ、サブモジュール、シンボリックリンク、Windowsで展開できない名前があると停止する。必要なプロファイル・分割モデル等は同一リポジトリに含める。SDKが未ロードとして返すモデルや、実際の取得・出力エラーがある場合は停止する。対応可能ノードがない図は未確認として記録し、レビューを続ける。SDKが検出・通知しない依存欠落を完全に保証するものではないため、実機で図と本文の網羅性を照合する。

Git処理・資料コピー・差分生成には進捗画面とキャンセルを備える。Next Design SDKの出力処理中は進行ログを表示し、その呼び出し自体は強制中断しない。失敗したセッションはターミナル再開の対象にせず、処理段階・診断ログを案内する。取得済みの途中ファイルは診断用に残す。

### 工程と上位文書の選択

1. レビューするモデルを選び、「レビュー開始」を押す。
2. 対象工程（要件分析／アーキ設計／詳細設計）を選ぶ。詳細設計ではアーキ設計、アーキ設計では要件分析書を上位文書として案内する。
3. モデルツリーから上位モデルをチェックする。配下も含めて出力する。モデル名・パスで検索でき、同名モデルは選択済み一覧のフルパスで区別できる。資料は「資料ファイルを追加」で選ぶ。
4. 「レビュー開始」を押す。工程はセッションに引き継がれ、エージェントから同じ工程を再質問されない。上位文書を指定しない場合は「今回は上位文書なし」を押す。理由の入力は不要で、上位整合は未確認として記録する。
5. 指摘は `review/review.md`、要求対応表は `review/coverage.md` に出力され、「結果を開く」で確認できる。

選択画面は毎回表示する。工程と上位文書の組み合わせはプロジェクト・工程ごとに復元する。工程を切り替えても編集中の選択は保持する。「今回は上位文書なし」では保存済みの上位文書を消さず、「キャンセル」では保存・出力・起動を行わない。

工程・上位文書の指定は「レビュー開始」に集約した。設定は `%USERPROFILE%\.nd-agent-review\projects\<プロジェクトパスのハッシュ>\review-selection.xml` に保持する。旧 `review-inputs.ini` の上位文書指定は初回候補として読み込む。過去版検証の対象は実行時に画面から選ぶ。プロジェクトを移動すると別設定になる。未保存のプロジェクトでは今回だけ選択してレビューできるが、選択は保存しない。

選択画面は拡張内の C# から Windows Forms で表示する。PowerShell・外部UIプロセス・スクリプトファイルは使わない。モデル情報を取得してから画面専用の STA スレッドへ渡し、画面から Next Design のモデルを直接操作しない。

セッション内の `inputs.md` に入力の出典、取得日時、対象モデルID、資料のSHA-256、出力警告が残る。上位モデルは `upstream/models/`、外部資料は `upstream/files/` に格納する。モデルは未保存の編集を含む現在の値、外部資料はディスク上の値を取得する。外部資料の未保存の編集は先に保存しておく。

リンク／ジャンクション経由の資料や Attachment は、親フォルダを含めて実体パスを解決し、通常のファイルとして固定コピーする。リンク自体は複製しない。リンク解決後にコピー元とコピー先が重なる場合、リンクが循環する場合、コピー先を参照する場合、実体を読み取れない場合は停止する。コピーに失敗した場合はAIを起動せず、生成途中のセッションを再開対象から除外する。Excel・Word・PDFの内容読解はエージェント側の環境に依存し、読めなかった範囲は判断不能として残す。

Next Design V3.x のスクリプト拡張。設計情報をエクスポートし、ターミナル上の
Claude Code / Codex エージェントと対話しながら設計レビューと修正提案の生成を行う。

## 役割分担

- **本拡張**: 設計情報のエクスポート / エージェント向け指示書の生成 / ターミナルでのエージェント起動 / 結果ファイルの表示
- **対話**: ターミナル上の claude / codex 本来の UI（V3.x の拡張 UI では対話画面を作れないため）
- **自動修正の範囲**: レビュー指摘（review.md）と修正提案（proposal.md / proposed/*.puml）のファイル出力まで。
  Next Design のモデルへの直接書き戻しは行わない（V3.x は読み取り専用要素が多いため）

## 使い方

1. ナビゲータでレビュー対象のモデル（またはプロジェクト）を選択する
2. リボン「AI レビュー」タブの **レビュー開始** を押す
   - 初回は基点フォルダを選択する（設定に記憶される）
   - 新規設定のエージェントは Codex。既存の有効な `agent=claude` 設定は維持される
   - セッションフォルダが作成され、設計情報が `design\design.md` にエクスポートされ、ターミナルでエージェントが起動する
3. 起動と同時に「レビューを開始してください」が自動投入される（`initialPrompt` で変更・無効化可）。**design-review スキル**に従い、選択画面で確定した工程の観点表でレビューする。工程の再入力は不要
4. 指摘は `review\review.md`、修正提案は `review\proposal.md` に出力される。リボンの **結果を開く** でセッション全体を VS Code の新しいウィンドウに開き、存在する結果ファイルを Markdown プレビューで表示する
5. 対話を中断した後は **ターミナル再開** で続きから再開できる

プロジェクトファイルと同じディレクトリに `Attachment` フォルダがあれば、その中身（Excel 等の別紙）を `design\Attachment` に固定コピーする。原本の後日変更はセッションに反映されない。コピーに失敗した場合はレビュー開始を止める。

図（シーケンス図・クラス図・状態遷移図）は自動で `design\diagrams\<種別>\<グループ以下の階層>\*.puml`（種別フォルダ: クラス図／シーケンス図／状態遷移図。該当する図がある種別のみ作成）に出力され、design.md の該当箇所から参照される（一覧は `design\_index.md`）。シーケンス図・状態遷移図の構成要素（メッセージ・状態など）はテキストには出力せず .puml に委ねる。出力エンジンは PlantUmlTool からの転記（修正は PlantUmlTool 側で検証してから反映すること）。

レビューなしで設計情報だけ出力する場合は、リボン「出力」グループの **設計情報を出力** を押す。出力先フォルダを毎回選択し、そこへ `design.md` + `diagrams\<種別>\<グループ以下の階層>\*.puml` + `_index.md` を直接出力する（セッションフォルダは作らず、エージェントも起動しない。Attachment のリンクも行わない）。

## レビュー結果を VS Code で確認する（0.9.0）

「結果を開く」は最新セッションを対象にする。エクスプローラーのツリーから `design/`・`review/` をたどり、レビュー結果と設計情報を同じウィンドウで確認できる。`review.md`・`proposal.md` が両方あれば両方を開き、片方だけなら存在する方を開く。結果がまだなければ案内を表示し、空のファイルは作らない。

セッション直下の `agentreview-results.code-workspace` は「結果を開く」のたびに生成する専用ファイル。このワークスペース内で結果の2ファイルだけを標準 Markdown プレビューに関連付ける。ユーザーの VS Code 設定や既存の `.vscode/settings.json` は変更しない。編集表示へ切り替える場合は VS Code の「エディターを再度開く…」からテキストエディターを選ぶ。

VS Code は通常のユーザー用・システム用インストール先と PATH から自動検出する。独自の場所にインストールしている場合は、「設定」の基本設定にある「VS Code」の参照ボタンで `Code.exe` を選ぶ。見つからない場合や起動に失敗した場合は案内を表示し、メモ帳には切り替えない。

0.9.0 を適用するには拡張機能一式を更新し、Next Design を再起動する。VS Code が未起動の場合と起動済みの場合の両方で「結果を開く」を実行し、セッションのツリー、結果のプレビュー、表・見出し・相対リンクを確認する。プロセス起動に成功しても表示の完了までは拡張から検知しない。

「設定」は基本設定・詳細設定の画面を開く。「フォルダを開く」「エクスポート診断」「スキルを開く」の動作は変更しない。既存の Claude 設定で Codex に切り替えたい場合は「エージェント切替」を使う。

## 図の出力階層

図グループの名前から図の親モデルまでをディレクトリにし、グループより上の設計書などは省く。図だけを選んだ場合も祖先のグループをたどる。所有関係に同種のグループが複数ある場合は最上位からの階層を保つ。

0.8.1 以降は設定不要。祖先モデルの所有フィールドに、出力する図と同じメタクラス完全名の型が宣言されているかを調べ、該当する最上位の祖先から出力する。参照フィールドは判定に使わない。図名やモデル名、プロファイル固有の型名をコードへ埋め込む方式ではない。

自動判別とは異なる起点を指定したい場合だけ、「設定」→「詳細設定」→「図の階層ルール」で、管理者が用意した UTF-8 の対応表を選ぶ。通常の利用では作成・指定は不要。該当する明示設定があれば自動判別より優先する。対応表の例（架空の型名）:

```ini
sequence=Example.Design.SequenceGroup
class=Example.Design.ClassGroup
state=Example.Design.StateGroup
```

同じ種別に複数の型を指定する場合はセミコロンで区切る。メタクラス完全名で大文字小文字を区別して一致させる。会社固有の対応表は Git 管理外の `.local/nd-knowledge/` に置く。対応表が未設定なら自動判別し、指定ファイルの読込失敗・不正値は警告して自動判別を続ける。明示設定に該当する祖先がない場合も自動判別する。

グループを判別できない図は警告し、図の直接の親だけをディレクトリにする。親も取得できなければ種別フォルダ直下に置く。選択モデルからの長い階層には切り替えない。この代替処理ではグループから親までの中間階層は復元できない。

異なるグループや子モデルの出力名が衝突した場合は、モデルID由来のハッシュを付けて分離する。同じフォルダの同名図はエディタID由来のハッシュで区別する。禁止文字は置換し、Windows の予約名には接頭辞を付ける。元のモデルパスは `_index.md` に残る。名前の衝突対象が増減するとハッシュの付与有無が変わることがある。

図を書き込めなかった場合は警告を出し、その図へのリンクを本文・索引へ載せない。他の図は引き続き出力する。図が0件でも索引は更新する。旧ファイルは自動削除しないため、更新後の初回や出力対象を変更するときは新しい出力フォルダを使う。レビューは索引と本文に載った図を対象にする。

修正後の図は `review/proposed/<種別>/<グループ以下の相対パス>` に置き、入力との対応を保つ。

### 0.8.1 の適用と確認

1. `main.cs`・`manifest.json`・`skills` を含む拡張機能一式を既存の配置先へ更新する。
2. 対応表の追加設定は不要。0.8.0 で設定した対応表を使い続けてもよい。自動判別へ戻す場合は 「設定」→「詳細設定」の「図の階層ルール」を空欄にして保存する。
3. Next Design を再起動し、3種類の図があるモデルを選択して、新しいフォルダへ「設計情報を出力」する。
4. グループ名からの階層、別グループにある同名図、`design.md` と `_index.md` のリンク、出力ウィンドウの警告を確認する。

```
│   │   ├── クラス図\       グループ名\子階層\図名_class.puml
│   │   ├── シーケンス図\   グループ名\子階層\図名_seq.puml

│   └── Attachment\         → プロジェクトファイルと同じ場所の Attachment の固定コピー

├── review\                 エージェントの出力（review.md / proposal.md / proposed\）

```

## design-review スキル

レビューの進め方と工程別観点は Agent Skill として渡す。エージェントは `session.ini` の確定済み工程を読み、
`references/` の観点表（要求分析 / アーキ設計 / 詳細設計）を適用してレビューする。

原本は拡張機能に同梱した `skills/design-review/`。リボンの **スキルを開く** ボタンで、
実行中の拡張機能にある原本フォルダを開く。各セッションの `.agents/skills` と `.claude/skills` は、
同じ同梱 `skills` をジャンクションで直接参照する。レビュー中はリンク先を含めて編集禁止。

観点を変更するときはリポジトリの `skills/design-review/` を修正し、拡張機能一式としてチームへ配布する。
スクリプトへの再埋め込みや個人用フォルダへのコピーは不要。同じ配置先で更新すれば、
この方式で作成した既存セッションからも更新後のファイルを参照する。
起動済みエージェントが読み込み済みの内容を自動で再読込することは保証しない。

レビュー開始時に `SKILL.md` と3つの工程別観点表の存在を確認する。不足していれば対象パスを表示して中止する。
ジャンクション作成に失敗した場合も、リンク元・リンク先とエラーを表示して中止し、エージェントは起動しない。
コピーへの切替は行わない。途中まで作成したセッションフォルダは調査用に残す。

### 旧コピー方式からの更新

1. `skills` を含む AgentReview フォルダ一式を、既存の配置先へ更新する。
2. 旧ユーザー用の `%USERPROFILE%\.nd-agent-review\skills` を手動削除する。`config.ini` は残す。
3. Next Design を再起動し、新規レビューを開始する。

旧カスタマイズの移行、旧セッションの変換、使用したスキルのバージョン・ハッシュ記録は行わない。
スキルの個別コピーや上書き設定は設けず、チーム共通の配布版を使う。

## 設定

リボンの **設定** ボタンから設定画面を開く。設定ファイルの編集は不要。

- 基本設定: エージェントとターミナルは選択式。レビュー保存先と VS Code は参照ボタンで指定する。追加のレビュー観点は任意入力。
- 詳細設定: CLIコマンド・追加引数・開始メッセージ・既存の図階層ルールを指定する。通常は既定値のままでよい。
- 「保存」で反映し、「キャンセル」や閉じる操作では変更しない。既存の設定値は画面に復元する。

保存先は `%USERPROFILE%\.nd-agent-review\config.ini`。以下は保守用のキー一覧。
ボタン操作のたびに読み直されるため、保存すれば Next Design の再起動なしで反映される。

| キー | 意味 |
|---|---|
| `agent` | 使用するエージェント（`codex` が既定 / `claude`）。未指定・空・不正値も Codex。「エージェント切替」ボタンでも変更可 |
| `workspaceRoot` | セッションの基点フォルダ |
| `terminal` | `auto`（Windows Terminal があれば使う）/ `wt` / `cmd` |
| `claude.command` / `codex.command` | CLI コマンド名 |
| `claude.args` / `codex.args` | 対話起動時の追加引数（例: `--permission-mode acceptEdits`） |
| `initialPrompt` | レビュー開始時に自動投入する最初のプロンプト（既定: レビューを開始してください。空なら手入力） |
| `diagramGroups.rulesFile` | 任意の図グループ対応表の絶対パス。未設定なら所有フィールドから自動判別 |
| `vscode.executable` | 結果表示用 `Code.exe` の絶対パス。未設定なら通常のインストール先と PATH から自動検出 |
| `perspectives` | レビュー観点（カンマ区切り。指示書に埋め込まれる） |

## 制約・注意

- design.md に出ない情報がある場合は、対象モデルを選択して **エクスポート診断** を実行すると、フィールド構成（RichText の有無など）・子モデル・エディタが出力ウィンドウにダンプされる（プロファイル依存の調査用）
- スクリプトの変更は Next Design を再起動するまで反映されない
- エージェントの実行完了を拡張は検知しない。「結果を開く」でファイルの有無を確認する
- 配置前検証: `python <skills>/nextdesign-script-extension/scripts/validate_manifest.py AgentReview --nd-version 3`

## 選択画面が起動しない場合

0.12.0 は PowerShell の実行に依存しない。旧版で「スクリプトの実行が無効」「UnauthorizedAccess」が出た場合は、拡張フォルダ一式を更新して Next Design を再起動する。旧 `resources/Select-ReviewInputs.ps1` は不要で、残っていても読み込まない。実行ポリシーの変更は不要。

C# の画面表示・入力検証・設定保存で失敗した場合は、例外本文をダイアログへ表示し、詳細を `%USERPROFILE%\.nd-agent-review\diagnostics\picker-*.txt` に保存する。ログのフルパスも表示する。Next Design 実機での表示は未確認。

## 過去版検証の出力先（0.12.4）

「設定」のレビュー保存先の下に `historical-probe-<識別子>/` を作成する。保存先が未設定の場合は検証時に選ぶ。

- `probe.md`: 検証レポート。本文・図一覧へのリンク、コピー記録、出力件数、警告、過去版の解放結果。
- `design/design.md`: 設計本文。
- `design/_index.md`: 図の一覧。
- `design/diagrams/`: 図のPlantUML。
- `project/`: 読み込み用に複製した過去版一式。

完了画面に保存先と出力内容を表示する。「はい」でVS Codeにフォルダ全体と検証レポートを開く。「いいえ」でも出力は残る。VS Codeが起動できない場合は、出力済みであることと保存先を案内する。図の内容・未保存編集の保持は実機で確認する。

## 過去版の出力範囲（0.12.5）

現在版で対象の工程成果物モデルを選択してから「過去版出力の検証」を実行する。選択モデルのIDを過去版と照合し、一致するモデルとその配下だけを出力する。名称や配置が変わっていてもIDが一致すれば対象とする。

プロジェクト全体の選択は受け付けない。過去版に同じIDのモデルがない、複数存在する、削除済み・未ロードの場合は停止し、全体出力や同名モデルへの置き換えはしない。読み込みに必要な `project/` のコピーは引き続き過去版一式を保持する。

実機ではアーキ設計と詳細設計に図がある過去版を使い、詳細設計モデルを選択して本文・図一覧・PlantUMLに他工程が混在しないことを確認する。`probe.md` の出力対象パスとモデルIDも照合する。

## 図のスキップと停止条件（0.13.1）

対応可能なノードやライフラインを取得できない図は、空の図と断定せず `unverified-diagrams.md` に未確認として記録する。図一覧から参照でき、現在版・過去版・上位文書の各出力フォルダに生成する。このスキップだけではレビューを止めない。図の取得例外・書き込み失敗など、その他の出力警告では引き続き停止する。

比較索引にも未確認の図のIDを残す。出力可能から未確認への変化は内容変更として検出する。両版とも未確認なら図の内容の変更有無は判断できないため、差分なしの案内・AIレビューでも未確認範囲を明記する。

実機では今回停止した成果物で再実行し、レビュー開始・未確認一覧の記録・有効な図の出力を確認する。図の未確認一覧にあるビューの実際の内容はNext Design上で確認する。
