# 1. はじめに

ModelUpdateProbe 0.4.0は、画面で選んだシーケンス図のメッセージ1件の名前を変更し、読戻しと手動Undo/Redo後の結果を記録する実機検証用拡張です。IDの転記やJSON編集は不要です。

対象はWindows / Next Design v3系。開発PCでは模擬SDKと入力画面単体を検査しています。Next Design実機での更新・図への表示反映は未確認です。

# 2. 参照資料

- [実機結果の記録票](RESULTS.md)
- [APIと判定の説明](../docs/model-update-howto.md)

# 3. 前提条件

- 保存済みのプロジェクトのコピーを開いて検証します。
- 会社PC内に検証結果を保存します。記録にはモデル名・変更前後の値を含みます。
- 入力画面は拡張内で.NET FrameworkのWindows Formsを使って表示します。PowerShellや外部スクリプトの起動はありません。会社PCの実行ポリシーの変更は不要です。

# 4. 操作手順

## 4.1 更新版の配置

1. 会社PCのリポジトリで `git pull --ff-only` を実行します。
2. Next Designを終了し、既存の `ModelUpdateProbe` フォルダを取得した同名フォルダで入れ替えます。配置先は `%LOCALAPPDATA%\DENSO CREATE\Next Design\extensions\ModelUpdateProbe` です。
3. Next Designを起動し、保存済みのコピーを開きます。

## 4.2 メッセージの変更

1. シーケンス図を開き、図を持つモデルをナビゲータで選びます。
2. 「設計更新検証」タブの「メッセージを変更」を押します。
3. コピーの確認に答え、会社PC内の結果保存フォルダを選びます。
4. 入力画面の一覧からメッセージを選び、下の欄に変更後の名前を入力します。名前を変えていなければ確認ボタンは押せません。
5. 「変更内容を確認」を押し、次の確認画面で変更前後を見てOKを押します。
6. 結果画面を撮影し、図上のメッセージ表記も変わったか確認します。

一覧は作成順です。図の上からの順序とは限りません。同名のメッセージは一覧の番号で区別しますが、判別できなければキャンセルしてください。今回の画面では名前以外の属性を選ぶ必要はありません。

入力画面のキャンセル・閉じる操作ではモデルを変更しません。設定ファイルと診断一覧は拡張が自動作成します。メモ帳で編集する操作は不要です。

## 4.3 Undo/Redoの確認

1. 結果画面を閉じ、Next Design本体でUndoを実行します。
2. 拡張の「Undo後」を押し、照合結果を撮影します。
3. 本体でRedoを実行し、拡張の「Redo後」を押して撮影します。

拡張の照合ボタンは値を読むだけです。本体のUndo/Redo操作を自動実行しません。途中で他の編集を挟まず、検証後は変更を取り消してください。プロジェクトの開き直し・再読み込み後は「メッセージを変更」からやり直します。

# 5. 停止した場合

停止した画面を撮影して渡してください。JSON編集やID調査は不要です。

| コード | 意味 |
|---|---|
| C001 / C002 | 準備状態 / 開いているプロジェクトがない |
| C003 | 準備時と現在のプロジェクトIDまたは保存先が違う |
| C004 / C005 | 対象が欠落・削除済み / プロキシ |
| C006 / C007 | 保存先が未確定 / 再取得した対象の種類が違う |
| S001〜S004 | 相互作用モデルの選択・対象メッセージの所属に関する停止 |
| U001 | 名前を変更できるメッセージがない |
| 入力画面の表示失敗 | 「詳細（会社PC内）」を開き、例外の部分を撮影する。設定変更やファイル編集は不要 |
| U003 | 入力中に対象の名前が変わったため停止 |

値の読戻しと図の表示反映は別に記録します。「一致」と表示されても、図上の表記が変わらない場合はその旨を添えてください。

# 6. 開発側の検査

`python ModelUpdateProbe/tests/run_tests.py` で模擬SDK試験と入力画面の単体試験を実行します。入力画面は `main.cs` 内の `ProbeNativeDialog` です。.NET Frameworkのフォーム型を実行時に読み込み、専用のSTAスレッドで表示します。画面へ渡す情報は名前の文字列だけで、モデル操作はNext Design側のスレッドで行います。

従来のファイル指定による検証処理は模擬試験用にコード内に残していますが、コマンドとして公開していません。

0.4.0ではPowerShell入力画面と起動処理を削除しました。フォルダを入れ替える際は旧版をextensions外へ退避してから新版をコピーすると、古い補助ファイルも残りません。旧版の結果フォルダは診断記録として保持できます。
