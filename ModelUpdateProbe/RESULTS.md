# 実機検証の記録票

スクリーンショットの要約画面をこの順で貼り、空欄を分かる範囲で埋める。詳細ログの送付は不要。

| 項目 | 記入 |
|---|---|
| 拡張の版 | 0.2.0（結果タイトルで確認） |
| Next Design詳細版 | 未確認 |
| 実行日 | 未確認 |
| ケースID / 実行ID | 要約画面を参照 |
| プロファイルと版 | 未確認。共有できなければその旨のみ |
| コピーしたプロジェクトで実行したか | 未確認 |
| 途中に別の編集・再読み込みを挟んだか | 未確認 |

| 順序 | 添付する要約 | Next Design画面での観測 |
|---|---|---|
| 1 | 準備完了 | 候補数、モデルが変わっていないか |
| 2 | 変更後 | 目的の属性が変わったか。シーケンス図のメッセージ表記にも反映されたか |
| 3 | 本体Undoを実行した後の照合 | 元の値に戻ったか |
| 4 | 本体Redoを実行した後の照合 | 変更値に戻ったか |

失敗した場合は、その段階で止めて画面を渡す。起動・コンパイル失敗ならSystem出力の行番号とメッセージを代わりに記録する。読めない文字は「判読不能」とする。

候補0なら「検証実行」を押さず、「フィールド診断」の画面を渡す。停止画面にC001〜C005が出たら、その画面と準備から停止までの操作順を渡す。詳細メッセージを開かなくてもコードで区別できる。

追加の非更新試験：確認画面でキャンセル／存在しないフィールド名／別モデルID／文字列以外のフィールド。それぞれ、モデルが変更されなかったことと表示された結果を記録する。

## 開発側の受領記録

- 出所：スクリーンショット／転記／ユーザー説明を区別する。
- 画像そのものを保存できない場合は、画像から読み取った記録だと明記する。
- 原文、対象環境、確認済み／推測／未確認を既存のローカル知識保存手順に沿って残す。
- 未観測のAPIや、別のプロファイル・版へ結果を一般化しない。

シーケンス検証では、準備画面のメッセージ数・ライフライン数・候補数も記録する。S001〜S004で停止した場合はコードと操作順を渡す。候補一覧の名称・値を含む写真は不要。
