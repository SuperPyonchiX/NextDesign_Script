# シーケンス生成実験 0.4.0

Next Design V3.1.9向けのC#スクリプト拡張。PlantUMLファイルを選び、内容を確認して、新しいシーケンス図を追加する。0.2.0の追加要素は実機未確認で、生成結果と診断を使って調整する。

既存の `ModelUpdateProbe` とは別フォルダで配置する。明示的なCommit/Rollbackの後にDisposeで終了処理を重ねない実装を継続する。Undo/Redoと保存後の再読込は実機で確認する。

0.2.1では、見本の図に複合フラグメントがある場合、その具体的な型と分岐の型を使用する。複数の型が混在するときは自動選択せず停止する。見本にない場合は従来のフィールド型を使う。シェイプ数の不一致は種類ごとの期待数・取得数を表示する。

0.2.2では、条件表示と後続要素の間に余白を設け、入れ子の枠を親の枠より内側に配置する。実機の文字サイズによる表示は別途確認する。

0.2.3ではrefも見本の図の具体型を使用する。refを取り込む際は、同期メッセージとref（相互作用の利用）がある図を開く。見本がない場合はインポート前に停止する。見本の参照先・本文はコピーしない。具体型による表示改善は実機で検証する。

0.2.4ではNoteも見本の図の具体型を使用し、その型から本文フィールドを取得する。Noteを取り込む際は、同期メッセージとNoteがある図を開く。見本がない場合はインポート前に停止する。見本の本文はコピーしない。複数のNote型がある場合は自動選択せず停止する。実機の生成・本文表示は別途検証する。

0.2.5では縦方向の固定余白を縮小する。メッセージ間隔は75から50、条件下の余白は50から40へ変更し、分岐の末尾・枠の前後・ライフライン末尾も詰める。Noteとrefの高さは本文行数から計算し、複数行メッセージと条件には行数分の余白を加える。既存の図には適用されず、取り込み直して生成する図に反映される。実機の文字重なりは別途確認する。

0.3.0では実行区間、自己メッセージ、返信を追加する。`skinparam sequenceMessageAlign`、`maxMessageSize`、`sequenceReferenceBackgroundColor` の単行指定は受け付けるが、見た目には反映せずNext Designの既定表示を使う。この差は取り込み前に表示する。新規構文の実機表示は未確認。

0.3.2では図外からの受信を追加する。`samples/08-incoming.puml` で外部信号から始まる実行区間と返信を検証できる。参加者1本の図にも対応する。送信元フレームと接続IDを照合するが、実機表示は未確認。

0.3.1では `A ->] : 本文` の右側への図外メッセージを追加する。受信先を新しい参加者ではなく図のフレームへ接続する。非同期・返信の矢印も扱う。`samples/07-outgoing.puml` で単独検証できる。受信先のフレームと接続IDを照合するが、実機表示は未確認。

0.3.6では `destroy A` によるライフラインの破棄点を追加する。既存のメッセージ種別を維持し、独立した破棄点として生成する。実行区間は破棄位置で閉じ、破棄後の送受信・二重破棄は事前検査で停止する。破棄後のactivate/deactivateは0.3.9から警告付きで除外する。`loop` の外で始めた実行区間を内側で閉じる配置も扱う。検証用は `samples/09-destroy.puml`。生成データ・公式SDKコンパイルは検査済み、破棄点の実機生成・表示は未確認。

0.3.7では破棄点からライフラインへの関連方向を修正する。破棄点側から関連定義を取得し、生成JSONの送信元・送信先の型をテストする。修正後の実機取り込み・表示は未確認。

0.3.8では破棄後再利用のエラーに対象の別名・破棄行・使用構文を表示する。「診断表示」には選択ファイルのパスと事前検査エラー行の前後を記録する。スレッドを破棄した後に別の参加者が返信する回帰テストを追加した。この並びの誤判定はローカルで再現しておらず、今回の変更は原因特定のための診断強化。

0.3.9では旧エクスポートに残る破棄後の `activate/deactivate` を除外する。除外件数と行番号を取り込み前の確認画面と結果に表示し、破棄点を維持する。破棄後の実際の送受信・二重破棄は引き続き停止する。実機取り込みは未確認。

0.3.10では破棄点の表示用の型を現在の図のビュー定義から取得する。見本がないときに汎用の基底型を使う処理をやめ、定義が複数ある場合は既存破棄点の型で選択する。特定できなければ取り込み前に停止する。破棄点の数の不一致には期待数と取得数を表示する。実機での改善は未確認。

## 既存図の更新へ向けた検証

更新方針は、PlantUMLを正として図全体を反映し、図自体のIDを維持する。0.4.0では前提となる同一IDへの再インポートを検証する。既存図を更新する機能はまだ提供しない。

1. コピーのプロジェクトで、異なるライフライン間の同期メッセージがある図を開く。
2. 「更新APIを検証」を押し、診断の保存先を選ぶ。PlantUMLの選択は不要。
3. 一時図を生成後、モデル・関連・図形のIDをすべて維持し、メッセージ名だけを変更したJSONを再取り込みする。
4. 同じモデルIDへの反映と図形を照合し、操作全体を取り消す。一時モデルの消去と親配下のモデルID一覧を検査する。
5. UPDATE001の結果を確認する。失敗時は「診断表示」も確認する。自動保存はしない。

既存図の削除やID変更は行わない。成功しても要素の追加・削除、図形置換、外部参照、保存再読込、Undo/Redoの保証にはならない。実機結果に基づいて更新処理を選ぶ。

## 配置と操作

1. `git pull` 後、`SequenceImportProbe` フォルダを他の拡張と同じ `extensions` フォルダへコピーする。ZIPの展開やビルドは不要。
2. Next Designを再起動する。
3. **コピーしたプロジェクト**を開く。異なるライフライン間の同期メッセージがある既存シーケンス図をメインエディタに表示する。
4. 「シーケンス生成実験」タブの「PlantUMLを取り込む」を押す。
5. まず同梱の `samples/01-async.puml` を選ぶ。コピーであることの確認後、ログの保存先を選ぶ。
6. 取り込み件数を確認して実行する。JSONやIDの入力は不要。
7. 元の図と同じ親の配下に追加された `Async sample` を開く。結果画面と新しい図のスクショを渡す。
8. 順に `02-fragments.puml`、`03-ref.puml`、`04-note.puml` を試す。個別に動いたら `05-all.puml` で混在を確認する。サンプルの書き換えは不要。
9. 実行区間・自己呼び出し・返信は `06-activation-self-reply.puml` で検証できる。実際のUTF-8 PlantUMLファイルも同じ操作で選べる。

「最小図を生成」も残している。PlantUMLからの生成で問題が出たときに、最小構成との比較に使える。

停止したら結果画面を渡す。原因の説明が足りない場合は「診断表示」で詳細を開ける。詳細にはプロファイルの属性名やIDが含まれる場合がある。ファイルを編集する必要はない。

失敗後は保存せずに検証用コピーを開き直してから再実行する。取消APIが正常終了しても、プロジェクト全体の復元が確認できたとは扱わない。

## 取り込み対象

| 要素 | この版の入力・動作 |
|---|---|
| 参加者 | `participant A`、`participant "表示名" as A`。メッセージ中の暗黙宣言も扱う |
| 同期 | `A -> B : request()` |
| 非同期 | `A ->> B : notify()`。同期と別のMessageSortで保存・照合 |
| 図外からの受信 | `[-> A : 本文`、`[->> A : 本文`、`[--> A : 本文`、`[-->> A : 本文`。受信先の約60px左にある独立メッセージ端から接続。実線の `->>` は非同期、破線は返信として扱う |
| 返信 | `A --> B : result`、`A -->> B : result` をReplyとして取り込む |
| 図外宛て | `A ->] : 本文`、`A ->>]`、`A -->]`、`A -->>]`。0.3.3では送信元から約60px左の独立メッセージ端へ接続する。フレーム・別ライフラインへは接続しない。消失記号の構文は未対応 |
| 自己メッセージ | `A -> A : operation()` など。送受信の高さをずらした折り返しを生成 |
| 破棄 | `destroy A`。独立した破棄点を生成し実行区間を閉じる。再生成と破棄メッセージ専用矢印は未対応 |
| 実行区間 | `activate A` / `deactivate A`。受信直後のactivateは受信先の実行区間を使用。入れ子を閉じると外側へ戻る |
| 表示設定 | `skinparam sequenceMessageAlign left/center/right`、正整数の `maxMessageSize`、6桁16進色の `sequenceReferenceBackgroundColor`。Next Design既定表示で代替する旨を確認画面に表示 |
| 複合フラグメント | `alt / else / end`、`opt`、`loop`、`par`、`break`、`critical`、`group`。条件・分岐と入れ子を生成。対応する演算子がプロファイルにない場合は実行前に停止 |
| 相互作用の利用 | `ref over A, B : 本文`、複数行の `end ref`。この版は枠と本文のみで、別の図への参照先は設定しない |
| Note | `note over A, B`、`note left of A`、`note right of B`。一行または `end note` で囲む本文。位置を生成し、アンカー線は生成しない |

UTF-8、1ファイル1図、300KB以下、参加者1〜50本、要素500件以下、入れ子8段まで。`@startuml` と `@enduml` が必要。左向き矢印、include、上表以外の表示設定・装飾指定などは未対応で、行番号を表示して停止する。未対応行を飛ばして図を作ることはしない。`activate/deactivate` は図内または各分岐内で対応させる。`loop` の境界をまたぐ開始・終了は扱う。`destroy` は対象の実行区間をまとめて閉じる。alt等の分岐をまたぐ実行区間の開始・終了や、色付きactivateはこの版では扱わない。

現在の図の型・構造関連・列挙値を取得し、新しいIDのモデル・関連・シェイプを生成する。`BeginUndoTransaction(false)` 内で `IProject.ImportUnitFromJson` を呼び、APIの警告・エラーがなく、読戻し照合が通った場合に確定する。Note本文がRichTextの場合は、同じトランザクション内で `SetRichTextField` を使って設定する。

照合するのは図の所属・名前、ライフラインとメッセージのシェイプ数、送受信先・種別・本文・実行区間への接続・送受信の高さ、実行区間の長さ、複合フラグメントの演算子と分岐の条件・所属・メッセージ、refとNoteのシェイプ数・本文。枠の位置や入れ子の表示、非同期矢印の見た目はスクショで確認する。API照合に成功しても、描画・Undo/Redo・保存後の再読込が確認済みになったとは扱わない。

この版は新規図への取り込み。既存図のIDや参照関係を維持した差分更新は未実装。

## 仮説と根拠

入力構造は[公式サンプルのプロジェクト](https://github.com/denso-create/NextDesign-Samples/blob/main/ndcli-extensions/ModelValidation/project/先進運転システムソフト開発.nproj)の保存形式を参照した。同梱の検証用PlantUMLは架空の内容とする。複合フラグメントと分岐の保存形式は公開サンプルに基づく。ref・Noteの保存形式と入れ子の関連付けには未検証の仮説が含まれる。プロファイル情報で事前検査し、生成後の読戻しと実機表示で切り分ける。

JSON形式で保存されたプロジェクトでは、先頭の `SchemaVersion` を利用する。取得できない保存形式では公式サンプルに見られた `13.0` を仮の値として使い、その判断をログに残す。保存形式の互換性、既定のシェイプスタイル、インポート時の整合性検査は実機で切り分ける。[API調査記録](../docs/sequence-import-api-research.md)も参照。

## 記録

保存先に `sequence_日時_ID` フォルダを作り、次を保存する。機密情報を含む可能性があるため会社PC内で扱う。

|---|---|

## 開発側の検査

```text
python SequenceImportProbe/tests/run_tests.py
python SequenceImportProbe/tests/run_tests.py --sdk-root work/sequence-api-research
python <skills>/nextdesign-script-extension/scripts/validate_manifest.py SequenceImportProbe --nd-version 3
```

1つ目はPlantUMLの解析、同期・非同期・返信種別、自己折り返し、実行区間の入れ子と復帰、分岐・入れ子、refとNoteの生成、未対応構文の拒否に加え、生成JSONのID独立性、所有構造、送受信、シェイプ、座標、文字列エスケープと不正入力を検査する。2つ目はさらに公式 `NextDesign.Core / Desktop 3.1.3.30714` と `.NET 6` 参照アセンブリで配布スクリプト全体をコンパイルする。SDKは開発PCの作業フォルダにのみ配置する。

これらの検査ではNext Designを起動しない。インポートの成功、失敗時の復元、実機の表示は保証しない。

図外矢印の構文は[PlantUML公式のIncoming and outgoing messages](https://plantuml.com/sequence-diagram)に基づく。Next DesignのSDKでは受信ポートにFrameを指定できる。0.3.3では希望する終了表示に合わせ、受信先にMessageEndを指定する。PlantUMLの右端表現をそのまま再現する配置ではない。

## 0.3.3: 終了メッセージを短い左向きに配置

既存入力の `A ->] : 本文` を変更せず、送信元の実行区間から約60px左に独立したメッセージ端を配置する。別ライフラインや図のフレームには接続しない。同期・非同期・返信の種類と本文は維持する。図外からの受信は従来どおり左側フレームから接続する。

端点の型はプロファイルの所有フィールドと、見本図にメッセージ端がある場合はその具体型から取得する。取り込み後にモデル・シェイプ数、受信先がMessageEndであること、ライフラインへ接続していないこと、端点の座標を照合する。不一致なら既存の取消処理で停止する。

ローカルではJSONの位置・接続検査と公式V3.1.3 SDKに対するコンパイルを確認。実機での丸い端点、矢印、文字位置は未確認。更新・再起動後に同じ入力を取り込み、最後のメッセージが短く左へ伸びることを確認する。既に生成した図は書き換えない。

根拠: [V3 IMessage の受信ポートと消失メッセージ](https://docs.nextdesign.app/extension/v3.x/api/NextDesign.Core/IMessage/)。

## 0.3.4: 外部からの受信も近傍の独立端点から接続

`[-> A`、`[->> A`、`[--> A`、`[-->> A` は、受信先の実行区間の約60px左に独立した送信端を置き、短い右向きのメッセージとして生成する。送信端をライフラインや図のフレームに接続しない。同期・非同期・返信の種類と、受信直後のactivateによる実行区間の再利用は維持する。

取り込み後は送信ポートの型・接続先・端点座標を照合する。ローカルの生成データ検査と公式SDKでのコンパイルを実施し、実機表示は更新・再起動後の再生成で確認する。

## 0.3.5: 独立端点の高さをメッセージに揃える

図外への送信・図外からの受信で、独立端点に適用していた上方向5pxの補正を削除した。端点のY座標をメッセージのSourceY・TargetYと同じ値にし、取り込み後にも3つの座標を照合する。左方向の距離は約60pxのまま。生成データ検査と公式SDKコンパイルで確認し、実機の水平表示は再生成して確認する。
